# Release 1.38.2 - MCP Apps Through Virtual Servers, Multiline Skill Descriptions

**November 2026**

---

## Upgrading from 1.38.1

This section covers everything you need to know to upgrade from 1.38.1 to 1.38.2.

### Breaking Changes

There are no breaking changes in this release.

### Other upgrade notes

- **A virtual server asks MCP App backends for their tools live.** With `TOOL_REFRESH_ENABLED=true`, 1.38.1 answered every non-egress backend's `tools/list` from the stored tool list. A backend with an MCP App tool is now asked live on each connect, like an egress backend, so its tools keep their `_meta` and `execution` fields. Other backends still answer from the stored list. (#2095)
- **Claude keeps a page it failed to show.** A user who saw "There was a problem displaying content" for an MCP App behind a virtual server should remove the connector and add it again after the upgrade, so Claude fetches the page again. (#2095)
- **SKILL.md frontmatter is parsed as YAML.** When the registry reads a SKILL.md to fill in a skill's name, description, version and tags (the registration form's parse step, `POST /api/skills/parse-skill-md`), it now uses a YAML parser, so folded (`>`) and literal (`|`) descriptions work. Frontmatter that is not valid YAML is ignored, and the name and description then come from the document body. This happens, for example, with an unquoted description containing `: `, one that starts with `[` or `@`, or one indented with tabs. An unquoted ` #` starts a YAML comment, so the rest of the line is dropped. Quote such descriptions. Skills already registered keep their stored values. (#2094)

### New Environment Variables

No new environment variables in this release.

### Upgrade Instructions

Deploy the 1.38.2 images for the registry, auth-server and mcpgw.

#### Docker Compose

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.38.2

./build_and_run.sh
```

#### Kubernetes / Helm (EKS)

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.38.2

# REQUIRED: the image tags in the subcharts changed, so rebuild the packaged dependencies
cd charts/mcp-gateway-registry-stack
helm dependency build
helm dependency update

# Update values.yaml if needed, then upgrade:
helm upgrade mcp-gateway . -f your-values.yaml
```

#### Terraform / ECS

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.38.2

cd terraform/aws-ecs
terraform plan
terraform apply
```

## Major Features

### MCP Apps through virtual servers

MCP Apps did not open through a virtual server in 1.38.1, for two separate reasons. This release fixes both. In Claude Cowork, the draw.io MCP App now renders through a virtual server, as it does on its direct route.

- With `TOOL_REFRESH_ENABLED=true`, 1.38.1 answered a virtual server's `tools/list` from the stored tool list. That copy keeps a tool's `title`, `annotations` and `outputSchema` but not its `_meta`, which holds the app's `ui://` page address, so MCP App tools reached clients without it. A backend with an MCP App tool is now asked live, and its tools keep `_meta` (vendor keys included) and `execution`.
- Claude shows an MCP App page only when its `_meta.ui.domain` is the hash of the connector URL the user added. The gateway corrects a backend's value on direct routes; on virtual servers it did not, so a page that sets the value, as draw.io does, was refused. The registry now computes the expected value for each connector path of a virtual server and writes it into the server's mapping, and the virtual router applies the same rule to `resources/read` replies.

Some limits remain on virtual servers, such as tools renamed by the virtual server and pages that rely on the client's UI capability reaching the backend. [MCP Apps](../mcp-apps.md) lists them, and #2034 tracks the rest of the work.

[PR #2095](https://github.com/agentic-community/mcp-gateway-registry/pull/2095)

## What's New

### Skills
- SKILL.md frontmatter is read with a data-only YAML loader. Folded and literal descriptions keep their text, quoted values keep their escapes, and `version: 1.10` stays the string `1.10`. The parser refuses aliases, explicit tags, invalid Unicode, nesting deeper than 32 levels and frontmatter over 64 KB. (#2094)

### Documentation
- [MCP Apps](../mcp-apps.md) now lists virtual servers as supported, with the limits that remain. [Virtual server operations](../virtual-server-operations.md) and [tool list refresh](../tool-list-refresh.md) say that MCP App backends are asked live. (#2095)

## Bug Fixes

- MCP App tools reached clients without their `_meta` through a virtual server when `TOOL_REFRESH_ENABLED` was on, so no app opened. (#2095)
- An MCP App page that sets `_meta.ui.domain` was refused by Claude behind a virtual server. (#2095)
- A SKILL.md description written as a folded or literal YAML block came through as `>` or `|`. (#2094)
