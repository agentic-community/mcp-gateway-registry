# Release 1.39.0 - REST APIs as MCP Servers, Read-Only Admins and a Tool Access Listing

**November 2026**

---

## Upgrading from 1.38.2

This section covers everything you need to know to upgrade from 1.38.2 to 1.39.0.

### Breaking Changes

- **Helm: move `registry.app.ssrfAllowedHosts` to `global.ssrfAllowedHosts`.** A stack install that sets the allowlist only under `registry.app.ssrfAllowedHosts` fails `helm upgrade` until the value moves to `global.ssrfAllowedHosts`, which the stack chart now passes to both the registry and the auth server. (#2100)
- **The auth server needs the same private-upstream allowlist as the registry.** Every MCP backend connection, virtual server backends included, now goes through the auth server's `/mcp-proxy` hop, pinned to the address the URL guard validated. A private upstream allowed only on the registry is refused at the hop with `502 Upstream MCP server blocked by egress policy`. Docker Compose, Terraform and Helm now pass `SSRF_ALLOWED_HOSTS`, `SSRF_ALLOWED_CIDRS` and `GATEWAY_PROXY_ALLOW_PRIVATE_TARGETS` to the auth server; a custom deployment must set them there too. (#2100)

### Other upgrade notes

- **Virtual server backends behave like direct routes.** Through the `/mcp-proxy` hop they now get TLS certificate verification, `MCP_PROXY_TIMEOUT` and the response body cap, and share the auth server's connection pool (`EGRESS_HTTP_POOL_MAX_CONNECTIONS` per worker). (#2100)
- **A forward proxy needs `EGRESS_FORWARD_PROXY_ENABLED=true`.** The guarded clients connect directly unless it is set, and startup now logs a warning when `HTTP_PROXY` or `HTTPS_PROXY` is set without it. (#2100)
- **Custom nginx templates need two lines in each `/validate` block.** MCP Apps on direct routes now get their Claude `ui.domain` from the exact URL the client connected to, which nginx passes to `/validate`. The bundled templates already carry these lines; a template you maintain yourself needs them in every `/validate` location, plus `map $host $mcp_connector_url { default ""; }` at the top level. Without them the page keeps the backend's value. (#2083)

  ```nginx
  proxy_set_header X-Mcp-Connector-Binding "{{NGINX_MARKER_SECRET}}";
  proxy_set_header X-Mcp-Connector-URL $mcp_connector_url;
  ```

- **OpenAPI MCP servers are off by default.** With `OPENAPI_MCP_ENABLED=false` no container is deployed and no route is registered. On Helm, `openapiMcp.enabled`, `registry.app.openapiMcpEnabled` and `auth-server.app.openapiMcpEnabled` must all match, or the stack chart refuses to render. (#2039)
- **Only admins and read-only admins see the tool access listing by default.** Set `TOOL_ACCESS_OWNER_VIEW=owned` to let a server's owner see who can use its tools. (#2103)

### New Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENAPI_MCP_ENABLED` | `false` | Turns on OpenAPI MCP servers. Targets with per-user keys also need `EGRESS_AUTH_ENABLED=true` and a secret store. |
| `OPENAPI_MCP_SYNC_SECRET` | none (required when enabled) | **(secret)** Signs the registry's calls to the `openapi-mcp` container. At least 32 random characters, different from `SECRET_KEY`, the same on the registry and the container. |
| `OPENAPI_MCP_INTERNAL_URL` | `http://openapi-mcp:9876` | Where the registry and nginx reach the container. Must be a hostname, not an IP address. |
| `OPENAPI_MCP_MAX_SERVERS` | `10` | OpenAPI MCP servers per deployment (1 to 100). |
| `OPENAPI_MCP_MAX_TARGETS_PER_SERVER` | `10` | REST targets per server (1 to 50). |
| `OPENAPI_MCP_MAX_TOOLS_PER_TARGET` | `100` | Tools one target may produce after its include filters (1 to 500). |
| `OPENAPI_MCP_SPEC_MAX_BYTES` | `5242880` | Largest spec, fetched or uploaded (1024 to 20971520 bytes). |
| `OPENAPI_MCP_RECONCILE_INTERVAL_SECONDS` | `60` | Seconds between full comparisons of stored and running state (10 to 3600). |
| `OPENAPI_MCP_BACKEND_TIMEOUT_SECONDS` | `30` | Container only: timeout for each backend REST call. |
| `OPENAPI_MCP_MAX_RESPONSE_BYTES` | `2097152` | Container only: largest backend response passed to the agent. |
| `OPENAPI_MCP_CONVERSION_TIMEOUT_SECONDS` | `10` | Container only: longest one spec conversion may take. |
| `TOOL_ACCESS_OWNER_VIEW` | `none` | `none`: only admins and read-only admins see the tool access listing. `owned`: a server's owner also sees its tools. |

Terraform adds the matching `openapi_mcp_*` variables (including `openapi_mcp_image_uri`, which must be a pinned tag) and `tool_access_owner_view`. Every parameter is in the [unified parameter reference](../unified-parameter-reference.md).

### Upgrade Instructions

Deploy the 1.39.0 images for the registry, auth-server and mcpgw, and the new `openapi-mcp` image if you turn the feature on.

#### Docker Compose

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.39.0

# Review new env vars in .env.example and update your .env if needed
# Then rebuild and restart:
./build_and_run.sh
```

#### Kubernetes / Helm (EKS)

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.39.0

# REQUIRED: the stack chart has a new openapi-mcp dependency and the subcharts changed
cd charts/mcp-gateway-registry-stack
helm dependency build
helm dependency update

# Move registry.app.ssrfAllowedHosts to global.ssrfAllowedHosts if you set it, then upgrade:
helm upgrade mcp-gateway . -f your-values.yaml
```

#### Terraform / ECS

```bash
cd mcp-gateway-registry
git pull origin main
git checkout 1.39.0

# Update your .tfvars with any new variables
cd terraform/aws-ecs
terraform plan
terraform apply
```

## Major Features

### REST APIs as MCP servers

An admin can now turn REST APIs into an MCP server without writing any server code. The admin creates an OpenAPI MCP server in the registry and adds REST targets to it. Each target is an OpenAPI 3.x spec, given as a URL or uploaded, plus a base URL and a credential. Every operation in the spec becomes a tool, and agents reach the server through the gateway with the same login and access rules as any other MCP server.

- A new `openapi-mcp` container serves the tools. The registry owns all state and pushes it to the container with a short-lived, single-use signed token; a reconciler repairs drift at startup, every 60 seconds and after a container restart.
- A target uses one shared key the admin enters, or a key each user adds for themselves. Per-user keys live in the egress vault, are bound to the target's base URL, and reach the container only for the call that uses them.
- A target is admitted only after its URLs pass the SSRF guard, the spec parses as OpenAPI 3.x within the size and tool limits, and a dry-run conversion succeeds. The container forwards only MCP headers to the backend and redacts the credential it attached if the backend echoes it back.
- The UI, the API (`/api/openapi-servers`) and the CLI (`openapi-server-*` commands in `api/registry_management.py`) all manage servers and targets.

See [OpenAPI MCP servers](../openapi-mcp-servers.md) and the [design](../design/openapi-mcp-servers-design.md).

[PR #2039](https://github.com/agentic-community/mcp-gateway-registry/pull/2039)

### Read-only admins

A group with the `view_all` UI permission sees every MCP server, virtual server, agent, skill and custom entity record, including private and group-restricted ones, without being able to change anything. Members get no writes, ratings or health checks on what they see only through `view_all`, no Settings pages, no gateway tool access, and the same redaction of backend URLs and credentials as any other non-admin. Reads that would use a stored credential or change stored state stay closed: a server's connection settings, a skill's SKILL.md content and a live tool-list fetch. The UI explains why instead of showing a generic error.

[`cli/examples/read_only_admin.json`](../../cli/examples/read_only_admin.json) is a ready group. See [read-only groups](../faq/read-only-viewer-group.md#read-only-admin).

[PR #2101](https://github.com/agentic-community/mcp-gateway-registry/pull/2101)

### Tool access listing

A new Tool access page, `GET /api/tool-access` and the `tool-access-list` command list every tool on every MCP server, OpenAPI MCP server and virtual MCP server, with the groups that can see it in the registry and the groups that can call it through the gateway. Each column shows the groups that grant access by themselves and, when no single group covers every check, the groups needed together. A virtual server's tool lists the virtual server's grant, the backend's grant and each required group separately.

The registry works each row out from the stored groups with the same matching code the gateway uses for every call, so the listing cannot disagree with what the gateway enforces. Admins and read-only admins see every tool; server owners see their own servers' tools when `TOOL_ACCESS_OWNER_VIEW=owned`. The listing grants nothing.

See [Tool access listing](../tool-access-listing.md) and the [FAQ](../faq/which-groups-can-call-a-tool.md).

[PR #2103](https://github.com/agentic-community/mcp-gateway-registry/pull/2103)

## What's New

### Security
- Every MCP backend connection is pinned to the address the URL guard validated, so a hostname that rebinds after the check cannot redirect the connection. The registry's MCP SDK connections run on a pinned transport, and nginx no longer connects to a registrant URL directly: every virtual backend location goes through the auth server's `/mcp-proxy` hop, which strips nginx's routing headers before the backend. (#2100)
- The gateway signs the exact public URL a client connected to into the proxy token, and MCP Apps on direct routes get their Claude `ui.domain` from that signed value. Clients cannot set or override it. (#2083)
- The CLI and the API client no longer print any part of a token or credential in logs or output. (#2103)

### MCP Apps
- On a direct route, a connector URL with a path prefix, a trailing slash, escaped characters or a query string now gets the right Claude `ui.domain`, so the page opens. Virtual servers keep the precomputed values from 1.38.2. (#2083)

### Configuration
- `TOOL_ACCESS_OWNER_VIEW` controls whether server owners see the tool access listing, on Docker Compose, Terraform, Helm and the System Config page. (#2103)

### Infrastructure
- Docker builds take an `APT_CACHE_EPOCH` build argument. CI sets it per run, so released images still get fresh security updates; local builds reuse the cached `apt-get` layer. (#2093)
- New `openapi-mcp` image, Helm subchart and Terraform service. (#2039)

### Testing
- The release smoke test (`tests/e2e_release_test.py`) gains a ninth check: it creates a virtual MCP server that exposes one stored backend tool under an alias, checks that `tools/list` shows the alias and not the backend name, calls the alias, and deletes the server. (#2108)

### Documentation
- New pages: [OpenAPI MCP servers](../openapi-mcp-servers.md), [Tool access listing](../tool-access-listing.md), and the FAQ [How do I find out which groups can see or call a tool?](../faq/which-groups-can-call-a-tool.md). [Read-only groups](../faq/read-only-viewer-group.md) now covers the read-only admin, and [MCP Apps](../mcp-apps.md) describes the connector URL rules. (#2039, #2083, #2101, #2103)

## Bug Fixes

- A server registered with a base URL, whose endpoint redirects to `/mcp`, got no stored tools after the connection pinning in this release, so search, the tool catalog, virtual servers and the tool access listing treated it as having none. The pinned transport now leaves the caller's request URL alone, so the MCP SDK follows the same-origin redirect again. This never shipped in a release. (#2110)
- An egress token refresh that read a stale copy of the vault entry could overwrite a token another refresher had just rotated with `refresh_failed`. The refresher now reads the entry again before marking it failed. (#2091)
- When `REGISTRY_URL` is unset, direct routes leave an MCP App page's `ui.domain` unchanged instead of rewriting it to the hash of a localhost URL. (#2083)
